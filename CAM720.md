# CAM720 (`cam720://`) source

Adds local, cloud-free support for Jooan CAM720 cameras (JA-A12 / W8-U) to
go2rtc: live video, camera-mic audio, and **two-way talk** to the camera
speaker, all over the camera's LAN DTLS P2P (TUTK/Kalay). Jooan's cloud is not
used.

## Stream URL

```
cam720://<camera-ip>/<uid>?token=<device_pwd>
```

- `uid` — the camera's P2P UID (printed by the camera, or read from it locally).
- `token` — the 14-char `device_pwd`, baked into the camera at manufacture.
  Read it off the camera with the companion Home Assistant integration
  (OJ-Labs-Ltd/hass-jooan-cam720) or from the camera's own config CGI.

Example `go2rtc.yaml`:

```yaml
streams:
  crib: cam720://192.168.1.50/EB6...111A?token=xxxxxxxxxxxxxx
```

## Two-way talk

The camera accepts G.711 A-law, 16 kHz, mono. Push audio with go2rtc's normal
backchannel, e.g. from Home Assistant, or directly:

```
POST /api/streams?dst=crib&src=ffmpeg:<media>#audio=pcma/16000
```

`cmd/avdrive` sends a test tone to verify the speaker:

```
CAM_PASS=<device_pwd> go run ./cmd/avdrive <camera-ip> <uid>
```

## How it works

AV login on IOTC channels 0 and 1, then IPCAM_START (511) and 810, then the
speaker is started with IOCtrl 848 and A-law frames (160 bytes / 10 ms) stream
on channel 0 in the camera's frame format with its additive checksum. PSK is
`SHA256(device_pwd)`; the DTLS cipher is pinned to the suite the camera
advertises.

## Building for your architecture

The published release binary is `linux/arm64`. For any other processor or OS,
build it yourself. go2rtc is pure Go with no cgo, so this needs only the Go
toolchain, no C compiler and no system libraries, and you can build for one
architecture from a machine of another.

### 1. Find your target's architecture

On the machine that will run go2rtc, run:

```sh
uname -m
```

| `uname -m` prints | Use GOARCH | Notes |
|-------------------|------------|-------|
| `x86_64`          | `amd64`    | Most NAS, mini-PCs, Intel/AMD servers and VMs |
| `aarch64` / `arm64` | `arm64`  | Raspberry Pi 3/4/5 on 64-bit OS, Radxa ROCK, most modern SBCs |
| `armv7l` / `armv6l` | `arm`    | 32-bit Pi OS, Pi 2 and older; also set `GOARM=7` (or `6`) |
| `i686` / `i386`   | `386`      | Old 32-bit x86 |

On Windows use `amd64`; on a Mac, `arm64` for Apple Silicon or `amd64` for
Intel.

### 2. Install Go (build machine only)

Go 1.22 or newer. You do not need Go on the machine that will *run* the binary,
only on the one that builds it.

- Debian/Ubuntu/Pi OS: `sudo apt install golang-go` (if that gives an older
  version, install from https://go.dev/dl/ instead).
- Fedora: `sudo dnf install golang`
- macOS: `brew install go`
- Any OS: download from https://go.dev/dl/ and follow its install steps.

Check it: `go version` should print 1.22 or higher.

### 3. Get the source

```sh
git clone -b cam720 https://github.com/OJ-Labs-Ltd/go2rtc-cam720.git
cd go2rtc-cam720
```

### 4. Build

Build for the machine you are on:

```sh
go build -ldflags="-s -w" -o go2rtc .
```

Or build for a different target by setting `GOOS` and `GOARCH`. The binary is
statically linked, so copy it to any machine of that architecture and run it,
no dependencies to install:

```sh
# 64-bit x86 (most NAS, mini-PCs, VMs)
GOOS=linux   GOARCH=amd64        go build -ldflags="-s -w" -o go2rtc-linux-amd64 .
# 64-bit ARM (Pi 3/4/5 64-bit, ROCK, most SBCs)
GOOS=linux   GOARCH=arm64        go build -ldflags="-s -w" -o go2rtc-linux-arm64 .
# 32-bit ARM v7 (Pi 2, 32-bit Pi OS)
GOOS=linux   GOARCH=arm GOARM=7  go build -ldflags="-s -w" -o go2rtc-linux-armv7 .
# 32-bit x86
GOOS=linux   GOARCH=386          go build -ldflags="-s -w" -o go2rtc-linux-386 .
# macOS (Apple Silicon / Intel)
GOOS=darwin  GOARCH=arm64        go build -ldflags="-s -w" -o go2rtc-macos-arm64 .
GOOS=darwin  GOARCH=amd64        go build -ldflags="-s -w" -o go2rtc-macos-amd64 .
# Windows
GOOS=windows GOARCH=amd64        go build -ldflags="-s -w" -o go2rtc-win-amd64.exe .
```

The first build downloads Go module dependencies and takes a minute or two;
later builds are seconds. The result is a single ~19 MB file.

### 5. Verify and run

```sh
 ./go2rtc --version    # prints the go2rtc version it was built from
```

Create a `go2rtc.yaml` next to the binary with your camera as a stream (fill in
your camera's IP, UID and token, see the top of this file):

```yaml
api:
  listen: "127.0.0.1:1984"
streams:
  crib: cam720://192.168.1.50/EB6...111A?token=xxxxxxxxxxxxxx
```

Run it:

```sh
./go2rtc -c go2rtc.yaml
```

Confirm the speaker with the bundled tester (needs `ffmpeg` on PATH for your
own audio, but the tester generates its own tone):

```sh
CAM_PASS=<device_pwd> go run ./cmd/avdrive <camera-ip> <uid>
```

### 6. Run it as a service (Linux, optional)

To keep it running across reboots, install a systemd unit. Adjust the paths to
where you put the binary and config:

```ini
# /etc/systemd/system/go2rtc-cam720.service
[Unit]
Description=go2rtc (CAM720 fork)
After=network-online.target
Wants=network-online.target

[Service]
ExecStart=/usr/local/bin/go2rtc -c /etc/go2rtc/go2rtc.yaml
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now go2rtc-cam720
```

Then point Home Assistant (or the Jooan CAM720 integration's go2rtc URL option)
at this instance.

### Troubleshooting

- `go: command not found` — Go is not installed or not on `PATH` on the *build*
  machine. See step 2.
- `cannot execute binary file: Exec format error` — the binary's architecture
  does not match the machine running it. Rebuild with the right `GOARCH` from
  step 1.
- Handshake or auth errors at connect time — the `token` is wrong. It must be
  the camera's 14-character `device_pwd`.
- No sound but no error — check the camera is reachable on UDP 32761 and not
  firewalled off, and that nothing else holds the speaker (an app talking to
  the same camera).
