# CAM720 (`cam720://`) source

Adds local, cloud-free support for Jooan CAM720 cameras (JA-A12 / W8-U) to
go2rtc: live video, camera-mic audio, and **two-way talk** to the camera
speaker, all over the camera's LAN DTLS P2P (TUTK/Kalay). Jooan's cloud is not
used.

## Stream URL

```
cam720://<camera-ip>/<uid>?token=<device_pwd>
```

- `uid` — the camera's P2P UID (printed by the camera, or read from it locally).
- `token` — the 14-char `device_pwd`, baked into the camera at manufacture.
  Read it off the camera with the companion Home Assistant integration
  (OJ-Labs-Ltd/hass-jooan-cam720) or from the camera's own config CGI.

Example `go2rtc.yaml`:

```yaml
streams:
  crib: cam720://192.168.1.50/EB6...111A?token=xxxxxxxxxxxxxx
```

## Two-way talk

The camera accepts G.711 A-law, 16 kHz, mono. Push audio with go2rtc's normal
backchannel, e.g. from Home Assistant, or directly:

```
POST /api/streams?dst=crib&src=ffmpeg:<media>#audio=pcma/16000
```

`cmd/avdrive` sends a test tone to verify the speaker:

```
CAM_PASS=<device_pwd> go run ./cmd/avdrive <camera-ip> <uid>
```

## How it works

AV login on IOTC channels 0 and 1, then IPCAM_START (511) and 810, then the
speaker is started with IOCtrl 848 and A-law frames (160 bytes / 10 ms) stream
on channel 0 in the camera's frame format with its additive checksum. PSK is
`SHA256(device_pwd)`; the DTLS cipher is pinned to the suite the camera
advertises.

## Building for your architecture

The published release binary is `linux/arm64`. go2rtc is pure Go with no cgo,
so you can cross-compile for any target from any machine with Go 1.22+
installed. No C toolchain or libraries are needed.

Clone and build the `cam720` branch:

```sh
git clone -b cam720 https://github.com/OJ-Labs-Ltd/go2rtc-cam720.git
cd go2rtc-cam720
go build -ldflags="-s -w" -o go2rtc .            # for the machine you're on
```

Cross-compile for another target by setting `GOOS`/`GOARCH` (the binary is
static, so it runs on any Linux of that architecture):

```sh
# 64-bit x86 (most NAS, mini-PCs, VMs)
GOOS=linux GOARCH=amd64        go build -ldflags="-s -w" -o go2rtc-linux-amd64 .
# 64-bit ARM (Raspberry Pi 3/4/5 64-bit, ROCK, most SBCs)
GOOS=linux GOARCH=arm64        go build -ldflags="-s -w" -o go2rtc-linux-arm64 .
# 32-bit ARM v7 (Raspberry Pi 2, older 32-bit Pi OS)
GOOS=linux GOARCH=arm GOARM=7  go build -ldflags="-s -w" -o go2rtc-linux-armv7 .
# 32-bit x86
GOOS=linux GOARCH=386          go build -ldflags="-s -w" -o go2rtc-linux-386 .
# macOS (Apple Silicon / Intel)
GOOS=darwin GOARCH=arm64       go build -ldflags="-s -w" -o go2rtc-macos-arm64 .
GOOS=darwin GOARCH=amd64       go build -ldflags="-s -w" -o go2rtc-macos-amd64 .
# Windows
GOOS=windows GOARCH=amd64      go build -ldflags="-s -w" -o go2rtc-win-amd64.exe .
```

Not sure which to pick? Run `uname -m` on the target:
`x86_64` is `amd64`, `aarch64`/`arm64` is `arm64`, `armv7l` is `arm` with
`GOARM=7`.

Then run it with a config that has a `cam720://` stream (see above) and point
Home Assistant, or the Jooan CAM720 integration's go2rtc URL option, at it.
